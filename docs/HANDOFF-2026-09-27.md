## Project philosophy — read this before changing anything

**"Eager load everything."** There is deliberately NO code splitting: one blocking entry
chunk, all 12 routes and all profile cards in it, every route server-rendered to complete
HTML for crawlers. The single exception is framework internals (`decode`, `serverForms`).

Do not "improve" this by adding `lazy()`, route splitting, or `Suspense`-style deferral.
`scripts/verify-build.mjs` fails the build if an unexpected dynamic chunk appears, and
`verify:ssr` fails if a crawler ever receives different HTML than a browser. Both are
load-bearing product requirements, not accidents.

## Stack

solid-js 2.0.0-rc.8 · @solidjs/web 2.0.0-rc.8 · @solidjs/router 2.0.0-next.24 ·
@solidjs/meta 1.0.0-next.2 · vite 8.3.0 · @solidjs/vite-plugin 3.0.0-next.35.
Rendered with `await renderToStream(...)` (settled HTML, not progressive streaming).
Async is `createMemo(async …)` + `<Loading>`/`<Errored>` — Solid 2 replaced `Suspense`.
Props are never destructured; call sites pass values, not accessors.

**Hard constraint:** `scripts/patch-solid-ssr.mjs` string-patches two promise-lifecycle
sites inside `@solidjs/web` and hard-fails on any version other than `2.0.0-rc.8`. Any
Solid bump must re-verify those patches via `npm run build` (which runs
`scripts/verify-build.mjs`).

## Running the tests — this is not discoverable, so here it is

`npm run test:browser` now defaults to the wrangler/workerd path and needs NO env var.
It does require a live backend:

    ssh -f -N -L 18000:127.0.0.1:8000 archbox   # keeps the loopback tunnel open
    npx playwright install chromium             # one-time

`scripts/api-proxy.mjs` is a real pass-through to `127.0.0.1:18000`. Without the tunnel it
502s, the Worker renders its designed 503 page, and Playwright's health check times out
before any test runs — it looks like a broken suite but is a missing tunnel. Documented at
docs/ARCHITECTURE.md:53.

Full gate set: `npm run typecheck` (runs with --noUnusedLocals --noUnusedParameters, so
dead code fails), `npm test`, `npm run build`, `npm run verify:ssr`, `npm run test:browser`.
Current baseline: 202 unit tests / 32 files, 24 browser tests, all green.

# Task 1 — AdSense reports "Ads.txt status: Not found"

**The file already exists and looks correct.** Verified from production:
`https://scoracle.com/ads.txt` returns 200, `content-type: text/plain`,
`cf-cache-status: HIT`, and the body is the expected single line:

    google.com, pub-9821466912189944, DIRECT, f08c47fec0942fa0

It lives at `public/ads.txt` and is served by the ASSETS binding (wrangler.jsonc sets
`assets.not_found_handling: "none"`, so known files bypass the Worker). `robots.txt` has
`User-agent: * / Allow: /`. There is no user-agent or crawler gating in `src/middleware.ts`.
Publisher id `ca-pub-9821466912189944` is used in `src/Document.tsx` (loader via `useHead`)
and `src/components/solid/AdSlot.tsx` (via `PUBLIC_ADSENSE_PUBLISHER_ID`).

So the console result is almost certainly one of:
1. A **stale cached check** — AdSense polls periodically and the result can lag a deploy.
   Confirm when `public/ads.txt` first went live (`git log --diff-filter=A -- public/ads.txt`)
   against when the console last refreshed.
2. The AdSense property is registered against a **different host** — e.g. the
   `*.workers.dev` hostname rather than `scoracle.com`, or a www/apex variant. The
   authorized seller ID must match the property the console is checking.
3. A **line-format** rejection: the certification token `f08c47fec0942fa0` must be the one
   from this exact AdSense account; a token copied from another property yields exactly
   this "Not found" state even with correct syntax.

Deliverable: determine which of these it is, and fix what is fixable in code/config.
Add a check to `scripts/verify-live.mjs` (or `verify-build.mjs`) that asserts
`/ads.txt` returns 200 with a body matching the expected `google.com, pub-…, DIRECT, …`
shape, so a regression or a bad deploy is caught rather than discovered in the console.
Note the AdSense console UI itself is not something we can query from here — say plainly
what you verified and what still needs a human with console access.

# Task 2 — `Portal` for the lift backdrop (needs design + a browser test first)

`src/components/solid/ReadingTable.tsx` renders `.pane-lift-backdrop` as a
`position: fixed; inset: 0; z-index: 79` sibling. Its placement is deliberate and
documented: it "sits outside the resting panes' rotated containing blocks".
`@solidjs/web` exports `Portal` for exactly this ("layers that need to escape an
`overflow: hidden` ancestor").

Blocker: the lift has unit coverage in `src/components/solid/ReadingTable.test.tsx`
(happy-dom) but **no browser coverage**, and `Portal` would change fixed-position
stacking, z-index against the AppTray (45) and pop-outs (70), and the scroll-lock logic —
none of which happy-dom can validate. I declined it for that reason.

Do this in order:
1. Add `browser/lift.spec.ts` covering the lift interaction against the real workerd
   server: pick up a card, assert the backdrop is visible and clickable, Escape and
   click-out both put it down, focus returns, the URL is untouched, and the z-order is
   correct against the tray. Run it against the CURRENT code first — it must pass, or
   you've found a pre-existing bug worth reporting.
2. Only then make the `Portal` change, and keep that spec green.

Note the lifted card itself must NOT be portaled: it is enlarged by a same-node `zoom`
(`liftStyle`/`cardRefs`), and portaling remounts it. Only the backdrop is a candidate.

# Task 3 — sharing the profile-read memos (blocked on a documented contract)

`src/lib/data/profile-data.ts` (`useProfileRead`) and `src/lib/cards/deck-scores.ts`
(`createDeckScoreReader`) each wrap the same `query()` key in their own `createMemo`, so
one logical value carries ~2× the graph nodes and two independent `NotReadyError` paths.
Moving the memos to the provider (`memoProfileReads`) was attempted twice and reverted.

Blocker, discovered by attempting it: `createDeckScoreReader`'s docstring promises
*"Isolate errors per reader so one deck's outage cannot drop the other readings."* The
per-consumer `createMemo` **is** that isolation. Sharing them fails three browser tests:
`backend deadline yields a card error while sibling cards survive`, `a failed shared score
product stays isolated and retries through its card boundary`, and `a slow new route
immediately replaces the departing page with its skeleton`.

A second, separate hazard was also hit and is already fixed: `deckHasContent`
(`src/lib/cards/deck-content.ts`) must keep RAW reads, not shared memos. It awaits each
read inside its own per-card async boundary; reading a shared memo from inside that nested
async makes presence depend on whether the shared computation is resolved yet, which on a
cold cache mis-classified pending reads as "no content" and dealt only 3 of 7 tabs for the
**first visitor of a cold Worker** — silently, no error, no 5xx.
`verify:ssr` now pins the dealt set via `deckTabs` so that cannot regress unnoticed.

The design question worth solving: share a single resolved *value* per key while letting
each consumer keep its own error boundary and pending state — i.e. the isolation is
per-consumer, the computation is not. `createStore` / `createProjection` are the RC8
primitives for keyed/derived state; verify what actually exists in the installed types
before proposing anything (this repo's installed Solid 2 API differs from Solid 1 docs in
several places, and an earlier audit made that mistake).

Treat this as a design task with its own test pass, not a cleanup. Do not land it as a
drive-by.

## Working notes

- Verify claims against the installed types in `node_modules/`, not Solid 1 memory.
  Several plausible-sounding APIs here do not exist: `assets`/`useAssets`, `splitProps`
  (use `omit`), `createResource`, `Suspense`, `Index`, `batch`, `onMount`.
- Prefer a control test — make the change, revert it, confirm the test fails — over
  asserting a test is meaningful. That discipline is what caught two of my own wrong
  conclusions in this codebase.
- `merge()` is for component *inputs*; its return type keeps function sources as
  functions, so it cannot be spread into a JSX element.
- Third-party images (cdn.nba.com, static.www.nfl.com, Wikimedia) 404 intermittently and
  rate-limit under rapid page loads. Some browser assertions scope to first-party
  (`127.0.0.1`/`scoracle.com`) for that reason; keep that scoping.
- The Kansas City Chiefs crest URL in the API payload is permanently dead
  (`Kansas_City_Chiefs_logo.svg` on Wikimedia). It now degrades gracefully via `RowCrest`
  in `src/routes/leaderboard.tsx`, but the data itself is still wrong upstream.
- Deploy with `npm run cf:deploy` (build → verify:ssr → wrangler deploy → verify:live).
  Confirm production is on the new build by comparing the `entry-client-*.js` hash in the
  served HTML against `dist/client/assets/` — the edge can otherwise serve stale content.
